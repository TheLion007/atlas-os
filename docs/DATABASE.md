# Atlas OS — Database

PostgreSQL, embedded locally with PGlite (the schema was originally written for Supabase, hence `auth.uid()` and RLS). **SQL migrations under `db/migrations/` are the source of truth** for structure, constraints, triggers and RLS. Drizzle provides typed queries; a test asserts the Drizzle schema matches the migrated database. Design rationale: [`decisions/0001-accepted-architecture.md`](./decisions/0001-accepted-architecture.md).

> Status: **implemented** in `db/migrations/` (Phase 3b) and verified by `tests/sql/` (97 tests run against every migration in-process with PGlite, no Docker needed). Not yet applied to a hosted Supabase project.
>
> **Memory + Knowledge (ADR 0002, 2026-09-23):** Memory is object type #15 on this same spine — see the `object_type`/`edge_kind` rows, `memory_details`, `tags`/`object_tags` and `objects.color` below. Nothing about the model above changed; everything new is an extension.
>
> Implementation notes that refine the design below:
>
> - `edge_rules` is a real table (seeded in the migration) so the type matrix is data, and a test asserts it agrees with `src/domain/edge-rules.ts` for every kind × from × to combination. The same goes for every enum versus `src/domain/enums.ts`.
> - Detail tables tie to the spine with a composite key `(id, type, owner_id)`, so a detail row cannot have the wrong type _or_ a different owner than its object.
> - Writers of an acyclic edge kind are serialised with an advisory lock so two concurrent inserts cannot jointly close a cycle.
> - Soft-deleting an object soft-deletes its live edges. **Restoring an object does not resurrect edges**: each must be re-validated and re-created deliberately.
> - `app_settings.base_currency` has no default: the owner chooses it on first run (no hard-coded currency).
> - The `activity_log` is written only by a security-definer trigger; users can read their own rows but cannot insert, edit or delete them.
> - Activity is logged for: created, updated (with field-level `{from, to}`), deleted, restored, purged, related, unrelated. No-op updates are not logged.
> - Concurrency guarantees above are enforced in SQL. PGlite is single-connection, so cross-connection races are not exercised by the test suite.

## Model: shared spine + typed details + typed edges

```
objects  (spine, one row per object)  ──1:1──►  <type>_details  (type-specific fields)
   ▲
   └── edges (typed, directed) ── from_id, to_id ──► objects
```

Every object shares one spine so a single graph, search index and activity feed are possible. Typed tables get real columns, checks and foreign keys instead of JSON blobs.

### `edges`

| Column                                               | Notes                                            |
| ---------------------------------------------------- | ------------------------------------------------ |
| `id uuid pk`                                         |                                                  |
| `kind edge_kind`                                     |                                                  |
| `from_id`, `to_id uuid`                              | FKs to `objects`; `check (from_id <> to_id)`     |
| `label text null`                                    | e.g. `assignee`, `owner` on `references` edges   |
| `dependency_type`, `lag_days int`                    | only meaningful when `kind = depends_on` (check) |
| `owner_id`, `created_at`, `updated_at`, `deleted_at` |                                                  |

Constraints (enforced in the database, not only the app):

- **Unique** `(kind, from_id, to_id)` among non-deleted rows.
- **Type matrix** (trigger): each `kind` allows only certain `(from_type, to_type)` pairs.

  | Edge           | From                                                                                                                                     | To                                                                                          |
  | -------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
  | `contains`     | `project, sub_project, location`                                                                                                         | `sub_project, task, milestone, risk, decision, property, event` (and `location → location`) |
  | `depends_on`   | `project, sub_project, task, milestone, decision, estimate`                                                                              | same set                                                                                    |
  | `estimates`    | `estimate`                                                                                                                               | any object                                                                                  |
  | `funded_by`    | `project, sub_project, property, estimate`                                                                                               | `estimate`                                                                                  |
  | `located_at`   | any object except `location` and `memory` (a memory has no physical location — its visual context comes from a Project, see ADR 0002 §3) | `location`                                                                                  |
  | `references`   | any object                                                                                                                               | any object                                                                                  |
  | `about`        | `memory`                                                                                                                                 | any object except another `memory` (use `references` for a memory-about-a-memory link)      |
  | `supported_by` | `memory`                                                                                                                                 | `document`                                                                                  |
  | `derived_from` | `memory`                                                                                                                                 | any object, including another `memory` (a synthesised insight)                              |

- **Single parent** for `contains` (unique on `to_id` where `kind = 'contains'`), so roll-up is a tree.
- **Acyclic** `contains` and `depends_on` (trigger with recursive check).
- `references` is stored once and read in both directions (backlinks are a query).

### Indexes

`objects (type, status) where deleted_at is null` · GIN `tags` · GIN `search` · trigram `title` · `edges (from_id, kind)` · `edges (to_id, kind)` · partial unique indexes above · `location_details (lat, lng)` · `activity_log (at desc)`.

## Row-level security

Every table: RLS **enabled**; policies `owner_id = (select auth.uid())`; no access for `anon`. Detail tables carry their own `owner_id` (no cross-table policy joins). The Supabase auto-REST surface therefore exposes nothing to unauthenticated callers. `memory_details`, `tags` and `object_tags` join the exact same owner-only policy loop as every other table — no new security model (ADR 0002 §15). The future AI assistant reads Memory **only** through the retrieval layer (`src/domain/retrieval.ts`), which itself goes through this same owner-scoped path; there is no wider-access route for it to take.

## Derived values (never stored)

Project progress · risk level · milestone slip · scheduled dates · critical path · blocked state · capital curve per scenario · purchase date · yield · backlinks · scenario assumptions/derived dates · location hierarchy path. Computed by `src/domain/engine` (see ARCHITECTURE.md).

## Portable JSON export/import

```jsonc
{
  "format": "atlas-os.export",
  "version": 1,
  "exportedAt": "2026-09-21T00:00:00Z",
  "settings": { ... },
  "fxRates": [ ... ],
  "objects": [ { "id": "...", "type": "project", "title": "...", "status": "active", "tags": [], "confidence": null, "details": { ... } } ],
  "edges":   [ { "id": "...", "kind": "contains", "from": "...", "to": "...", "label": null, "dependencyType": null, "lagDays": null } ]
}
```

- IDs are preserved; the whole file is Zod-validated before anything is written.
- Import runs in one transaction. Modes: `merge` (upsert by id) and `replace`.
- Edges are validated against the same type matrix, single-parent and acyclicity rules as normal writes.
- Document _files_ are not embedded: the export carries metadata and `storage_path`; blobs are exported separately.
- Derived values are never exported.
